PART 3 — TURN MERGING & ALTERNATION
--------------------------------

INPUT STYLE 1: PASS-1 EPISODES

You will receive episodes with:

- episode_id
- lineage
- student_turns: list of objects (turn_index, text, behavior_tags, inferred_state, etc.)
- teacher_turns: list of objects (turn_index, text, phase, function_id, mechanism_shape, outcome, register, trap_ids, etc.)

Procedure:

1. Build a combined timeline:

   - For each student_turn → (turn_index, "student", data)  
   - For each teacher_turn → (turn_index, "teacher", data)  
   - Sort by turn_index ascending.

2. DISCARD leading teacher-only segments:

   - If the first one or more entries in the sorted timeline are teacher turns with no preceding student turn, SKIP ALL of those teacher turns.
   - Start from the first student turn you encounter.

3. MERGE consecutive turns of the same type:

   - Walk through the timeline from that first student turn.
   - If two or more consecutive entries are student turns:
     - Merge their texts into a single student “chunk” by concatenating with a blank line between them.
     - Treat this as ONE user message.
   - If two or more consecutive entries are teacher turns:
  	- Merge their texts into a single teacher “chunk” by concatenating with a blank line between them, in order.
	- For the [PEDAGOGY] metadata (phase, function_id, mechanism_shape, register, trap_ids, outcome, etc.), use the fields from the LAST teacher_turn in that merged block.
