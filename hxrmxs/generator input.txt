4. TURN ORDER, MERGING & STRICT ALTERNATION
============================================================

You MUST produce **strict alternation** after the system message:

system → user → assistant → user → assistant → ...

### 4.1 Build a sorted timeline

For each episode:

1. Collect all student_turns and teacher_turns.
2. For each, make a pair:

   (turn_index, "student", student_turn_obj)  
   (turn_index, "teacher", teacher_turn_obj)

3. Sort this combined list by turn_index ascending.

### 4.2 Drop teacher-first intro turns (ignoring empty students)

- A student_turn **counts** as a real start only if its text is non-empty after stripping whitespace.
- Find the first student_turn in the sorted list whose text, after stripping, is non-empty.
- If there is no such student_turn, **drop the entire episode** (do not output it).
- Otherwise, **drop all teacher_turns that occur before that student_turn**.

No assistant messages may appear before the first real user message.

### 4.3 Merge consecutive student turns → ONE user message

After dropping early teachers:

- Walk the sorted list.
- Group consecutive student_turns (no teacher_turn between them) into blocks.
- For each student block:

  - Remove any student_turn whose text is empty or whitespace-only.
  - If, after this removal, the block is empty → skip this block entirely.
  - Otherwise:
    - Concatenate the remaining student_turn.text fields in chronological order.
    - Insert **exactly one blank line** between each original student_turn.text.
    - Emit one user message:

      {
        "role": "user",
        "content": "<merged student text verbatim>"
      }

  - This merged user message is now the “previous student” for the next assistant.

### 4.4 Merge consecutive teacher turns → ONE assistant message

- After a user message, you may have one or more consecutive teacher_turns.
- Group consecutive teacher_turns (no intervening student_turn) into a block.
- For each teacher block:

  - Concatenate all teacher_turn.text fields in chronological order.
  - Insert **exactly one blank line** between each original teacher_turn.text.
  - Let LAST_TEACHER be the final teacher_turn in this block.
  - Build the [PEDAGOGY] block from LAST_TEACHER and the immediately preceding user message (the merged student block).
  - Emit one assistant message:

    {
      "role": "assistant",
      "content": "[PEDAGOGY]\n...fields...\n[/PEDAGOGY]\n\n<merged teacher text>"
    }

### 4.5 Enforce strict alternation & drop orphan final user

Your timeline → messages MUST look like:

system  
user  
assistant  
user  
assistant  
...  

If the episode ends with a user block that has **no following teacher_turn**, you MUST **omit** that final user message, so the conversation always ends on an assistant.

If, after all rules above, an episode has fewer than 1 user + 1 assistant (i.e. no complete pair), you MUST drop that episode entirely.
